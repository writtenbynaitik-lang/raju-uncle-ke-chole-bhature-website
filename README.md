# Raju Uncle Ke Chole Bhature — website concept

A website concept created as a visual showcase for **Raju Uncle Ke Chole Bhature**,
Bharati Vihar, Katraj–Dhankawadi, Pune.

It is a working site, not a mockup: real components, a real menu model, a real
ordering flow, real responsive behaviour.

```bash
npm install
npm run dev      # http://localhost:5177
npm run build    # type-check, bundle, then prerender dist/index.html
npm run preview  # serve the production build
npm run images   # re-run the photography pipeline
```

## What is on the page

| Section | Job |
| --- | --- |
| Hero | Name at signage scale, one plate, three ways to act |
| Running band | The restaurant's own words, in Hindi and English |
| The plate you came for | The brand moment — three frames, deliberately unequal |
| The one everyone talks about | The house plate, printed as large as the page allows |
| The menu | Three categories, tabbed, every card addable to an order |
| How hungry are you? | A way into the menu for people who do not read menus |
| The craving behind the name | Positioning, not history — no founder, year or record |
| The plate. The craving. The repeat. | Photography instead of invented reviews |
| Come hungry | Area, phone, call CTA, directions demo state |
| Order drawer | Pick, review the slip, call to order |

## Build

`npm run build` type-checks, bundles, renders the app once through
`react-dom/server` and bakes the markup into `dist/index.html`. The page then
paints from HTML alone and React hydrates over the top — which matters, because
this will mostly be opened on a phone on mobile data. The hero's
`<link rel="preload">` is generated by the image pipeline from the widths that
exist on disk, so it can never point at a file that is not there.

Over the wire on a first mobile view: ~81 KB of JS, ~8 KB of CSS, 62 KB of font
and a 32 KB hero image.

## Ground rules this build follows

Several businesses trade under the name "Raju Uncle Ke Chole Bhature", and their
aggregator listings are easy to confuse. Only two sources count as verified for
this prospect:

1. the restaurant's own site, **rajuunclekecholebhature.com**
2. the prospect record — phone number and area

**Verified, and on the page:** the name, the tagline *"Taste the Tradition!"*,
`+91 98237 87513`, Bharati Vihar / Katraj–Dhankawadi / Pune, pure-veg North
Indian.

**Not verified, and deliberately absent:** street address, PIN code, opening
hours, prices, ratings, reviews, dish lists, a Google Maps pin, and WhatsApp.
Every one of those exists on some listing under this name; none could be tied to
*this* branch, so none of it is here. `src/data/site.ts` carries the rule at the
top of the file, and nothing factual lives outside it and `menu.ts`.

**Where a channel is real but unconfirmed** — directions, online ordering — the
button opens a short labelled note saying what would connect there and what has
to be confirmed first. No dead buttons, no guessed URLs. Confirm the detail, fill
in one field, and the demo state becomes a live link.

Calling is the only confirmed channel, so calling is the primary action
throughout.

## Photography

`scripts/grade.py` is the whole pipeline. It pulls openly-licensed photographs
from Wikimedia Commons, normalises each frame's own colour cast and exposure,
then applies one house grade — warm daylight, blacks landing on the brand's cocoa
instead of black, highlights drifting to cream — so that two dozen photographs by
two dozen people read as a single commissioned shoot. It writes WebP at the
widths each asset is actually displayed at, plus:

- `src/data/images.ts` — the widths that exist on disk, so a `srcset` can never 404
- `src/data/credits.ts` — author, licence and source page for every photograph,
  rendered in the footer

**Replacing these with the restaurant's own photos** is a one-step job. Drop files
named after the keys in `scripts/photos.json` into `src-photography/`
(`hero-plate.jpg`, `dish-lassi.jpg`, …) and run `npm run images`. Local files win
over the downloaded ones, the same grade is applied, and the whole site re-skins
to the real kitchen. That is the intended path for a live build — the current
images stand in for photography that does not exist yet.

## Design system

- **Paper** `#F7F1E5` is the ground; **cocoa** `#211A16` is every word that matters.
- **Saffron** `#D9822B` is rationed. It is a *surface* on light ground (dark type
  on top, 5.9:1) and *type* on dark ground (6.7:1) — never small type on cream,
  where it measures 2.6:1 and fails.
- **Chilli** `#A93226` marks one thing per screen; **coriander** `#5D6B42` does the
  quiet work — veg dots, metadata.
- **Khand** (Indian Type Foundry, condensed, Latin + Devanagari) sets every
  headline. **Inter** sets body. **Rozha One** carries the short expressive lines
  and the Hindi. All self-hosted; the Devanagari faces are subset to the nine
  words the site actually sets, which takes them from 158 KB to 32 KB.

Tokens live in `src/styles/tokens.css`; each component owns its own CSS file.

## Accessibility

Semantic landmarks, one `h1`, a skip link, a real tablist with roving focus and
arrow keys, a modal drawer with focus trapping, Escape and focus restoration,
visible focus rings on both grounds, 44px+ targets, `prefers-reduced-motion`
honoured throughout (the running band stops and the reveals resolve), and body
text that clears 4.5:1 everywhere.
